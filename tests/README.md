# Parser regression tests

After ANY change to `parse_tab.py`, run:

```
python3 tests/run_regression.py
```

It re-parses every tab in `manifest.json` and compares against the saved
baselines, reporting a readable summary (measure counts, notes added/removed
per measure, note pile-ups) instead of a giant JSON diff. If a difference is
intended — and you have *visually checked it in the viewer* — accept it with
`--update-baselines`.

## What the baselines are

- `baselines/tubaka.json` — byte-identical to the committed
  `scores/tubaka.json` (verified 2026-06-10: current parser + the 2020
  Edition PDF reproduce it exactly).
- `baselines/jarabi.json` — output of the **current** parser on `Jarabi.pdf`
  (2026-06-10). NOTE: this differs from the committed `scores/jarabi.json`,
  which was generated by an older parser version (180 vs 184 measures,
  ±2 notes) and has never been visually re-verified against the new parser.
  The committed score also has a hand-edited `bpm: 200` — the parser default
  is 80 — so if jarabi is ever regenerated for the app, set bpm back to 200
  manually.
